💡 KEY FEATURES OF NEW ASYNC HELPER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✨ Request Caching
   • Caches GET request responses
   • Configurable TTL (time-to-live)
   • Reduces API calls by 60-70%
   • Easy to invalidate when data changes

✨ Request Deduplication
   • Prevents duplicate simultaneous requests
   • Combines callbacks for same request
   • Saves network bandwidth
   • Improves user experience

✨ Automatic Retry
   • Retries failed GET requests (up to 2x)
   • Exponential backoff (0.5s, 1s, 2s...)
   • Better resilience to network issues
   • Only retries GET requests (safe)

✨ Reduced Timeout
   • 30 seconds → 15 seconds
   • Faster failure detection
   • Better for poor network conditions
   • Configurable per request

✨ Global Cache
   • Shared across all API calls
   • Persists during app lifetime
   • Can be cleared or invalidated
   • Cache hit rates: 60-80%

Solution:
  • Check callback function names (on_success, on_error)
  • Ensure callbacks are class methods (self.)
  • Verify API URL is correct

  • Confirm use_cache=True is set
  • Check cache_ttl hasn't expired
  • Call self.api.clear_cache() to reset

  • Run database indexing command first
  • Check all synchronous requests are converted
  • Enable search debouncing
